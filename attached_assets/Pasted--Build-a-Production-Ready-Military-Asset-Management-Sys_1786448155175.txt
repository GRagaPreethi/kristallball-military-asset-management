* JWT token

`authenticateToken`

middleware that:

1. Reads Authorization Bearer token.

3. Rejects invalid/expired tokens.

Create:

`authorizeRoles(...roles)`

middleware.

# 6. Inventory Calculation

Do NOT maintain unreliable manually editable balance fields.

Calculate inventory from transaction history.

For a selected:

* Base
* Equipment Type
* Date range

calculate:

Opening Balance

*

Net Movement

*

Assigned

*

Expended

=

Closing Balance

Where:

Net Movement = Purchases + Transfers In - Transfers Out

For example:

Opening Balance = all valid stock-affecting transactions before the selected start date.

Current-period movement:

Purchases
+
Transfers In
------------

Transfers Out

Assigned = current-period assignments

Expended = current-period expenditures

Closing Balance must represent the actual available stock.

---

# 7. Critical Inventory Validation

Before allowing:

* transfer
* assignment
* expenditure

calculate the currently available stock.

Never allow:

available stock < requested quantity

Return a clear HTTP 400 response such as:

{
"message": "Insufficient inventory",
"available": 20,
"requested": 30
}

Never allow negative inventory.

---

# 8. Atomic Transfers

Transfer operations MUST use PostgreSQL transactions.

When creating a transfer:

1. BEGIN transaction
2. Authenticate requesting user
3. Validate role
4. Validate source/destination bases
5. Validate quantity > 0
6. Validate source and destination are different
7. Calculate available stock at source
8. Reject if insufficient stock
9. Insert transfer
10. Record audit log
11. COMMIT

If anything fails:

ROLLBACK

No partial transaction should remain.

The API should never report a transfer as successful if the database transaction failed.
